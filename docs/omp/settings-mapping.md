# OMP settings pages: keys and commands

Which OMP config keys, files and `omp` commands each settings page reads and writes. The rules
the settings engine enforces (env-set keys read-only, credentials reset-only, overlays, restart
required) are in [settings.md](settings.md). Every `omp` command below runs through
`OmpControlService` with the instance's `--profile`, under the deadlines in
[sidecar.md](sidecar.md#control-processes).

## Settings → OMP pages

Each page is `OmpSettingsPanel` (`apps/web/src/components/settings/OmpSettingsPage.tsx`) with
one page id from `OMP_SETTINGS_PAGES` (`packages/provider-omp/src/settingsPages.ts`). It works on
the primary environment's OMP instance, with a picker when that environment runs several.

Every page with keys reads and writes the same way:

| Action | Server method            | Command                                                                                               |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------- |
| Read   | `server.readOmpSettings` | `omp config list --json --cwd <stateDir>/omp`                                                         |
| Save   | `server.writeOmpSetting` | `omp config set --scope global --cwd <stateDir>/omp --json -- <key> <JSON>`, then `config list` again |
| Reset  | `server.resetOmpSetting` | `omp config reset --scope global --cwd <stateDir>/omp --json -- <key>`, then `config list` again      |

The pages write the global layer only. `<stateDir>/omp` holds no project config, so `config list`
there shows the global value. A key ending in `.` in the table below stands for every key in that
group; keys the running OMP does not register are left out of the form.

| Page (route)                                  | Config keys                                                                                                                                                                                                                                                                                                                                                                                                         | Also on the page                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |

## Files and commands beyond config keys

The agent directory is what `omp [--profile <p>] config path` prints for the instance, asked on
every call. Files are reached only inside it ([settings.md](settings.md#agent-directory-files)).

| Page             | What                                                             | Server method                                                       | OMP side                                                                                                                                                                                                          |
| ---------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Advisor & Agents | Advisor roster                                                   | `server.listOmpAgentFiles`, `readOmpAgentFile`, `writeOmpAgentFile` | `WATCHDOG.yml` (or an existing `WATCHDOG.yaml`)                                                                                                                                                                   |
| Advisor & Agents | Custom subagents                                                 | the same, plus `server.deleteOmpAgentFile`                          | `agents/<name>.md`                                                                                                                                                                                                |
| Custom providers | Model endpoints                                                  | `server.listOmpAgentFiles`, `readOmpAgentFile`, `writeOmpAgentFile` | `models.yml` (or an existing `models.yaml`); a save is first checked by an RPC control server in a scratch agent directory (`get_available_models`, 15 s) ([settings.md](settings.md#custom-providers-modelsyml)) |
| MCP              | MCP servers                                                      | `server.listOmpAgentFiles`, `readOmpAgentFile`, `writeOmpAgentFile` | `mcp.json`, `.mcp.json`                                                                                                                                                                                           |
| Customization    | Skills, rules, prompts, hooks, tools, agents                     | `server.listOmpAgentFiles`, `readOmpAgentFile`, `writeOmpAgentFile` | Paths allowed by `ompCustomizationPathAllowed` ([settings.md](settings.md#mcp-and-customization))                                                                                                                 |
| Customization    | Unpack bundled agents                                            | `server.unpackOmpAgents`                                            | `omp agents unpack --user --json`                                                                                                                                                                                 |
| Plugins          | Installed plugins                                                | `server.listOmpPlugins`                                             | `omp plugin list --json`, `omp plugin marketplace list`                                                                                                                                                           |
| Plugins          | Browse a marketplace                                             | `server.discoverOmpMarketplace`                                     | `omp plugin discover <name>`                                                                                                                                                                                      |
| Plugins          | Install, uninstall, enable, disable, add or remove a marketplace | `server.runOmpPluginCommand`                                        | `omp plugin install\|uninstall\|enable\|disable …`, `omp plugin marketplace add\|remove …`, after a confirmation that shows the command                                                                           |
| Plugins          | Reload plugins                                                   | `server.reloadOmpPlugins`                                           | RPC `prompt` `/reload-plugins` to each idle running thread                                                                                                                                                        |
| Plugins          | Check for updates                                                | `server.checkOmpUpdate`                                             | `omp update --check` (reports only; Ompanel never runs `omp update`)                                                                                                                                              |
| Skills           | Resolved skills                                                  | `server.listOmpSkills`                                              | `omp skill list <stateDir>/omp --json`                                                                                                                                                                            |

Plugin, marketplace and update commands run in `<stateDir>/omp`, so they act at user scope
([settings.md](settings.md#plugins-and-skills)).

## Settings → Providers → an OMP instance

The OMP instance card on Settings → Providers holds what is not an OMP config key.

| Section       | Reads and writes                                                                                                                               | OMP side                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Instance form | `binaryPath`, `profile` (`OmpSettings`, `packages/provider-omp/src/settings.ts`), stored in Ompanel's own settings                             | Nothing; they choose the binary and the `--profile` every `omp` call gets                                            |
| Status        | The provider snapshot                                                                                                                          | `omp --version`; RPC `ready`, `get_login_providers`, `get_available_models` ([sidecar.md](sidecar.md#status-checks)) |
| Setup         | The snapshot's `executable`                                                                                                                    | Types `<binary> [--profile <p>] setup` into a terminal for the user to run ([onboarding.md](onboarding.md))          |
| OMP sessions  | `server.listOmpSessions`, `server.importOmpSession`                                                                                            | Session files in OMP's sessions directory ([sessions.md](sessions.md#import))                                        |
| Accounts      | `server.listOmpAccounts`, `startOmpSignIn`, `subscribeOmpSignIn`, `answerOmpSignIn`, `cancelOmpSignIn`, `listOmpSignOutAccounts`, `ompSignOut` | RPC `get_login_providers`, `login`, `get_logout_accounts`, `logout` ([accounts.md](accounts.md))                     |

## Per-thread overrides

A thread's override (`server.setOmpThreadOverride`, `server.clearOmpThreadOverride`) uses a
session RPC command when one exists for the key, and otherwise the thread's `--config` overlay.
`tools.approvalMode` is never overridden per thread: the thread's permission mode sets
`--approval-mode`. The command list is in [settings.md](settings.md#per-thread-overrides).

## PRD §7 rows that moved

| PRD §7 row                                                    | Where it is                                                                                                                                                                                                    |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install: sidecar path, profile                                | Settings → Providers → OMP instance                                                                                                                                                                            |
| Auth: login providers, `auth.broker.url`, `auth.broker.token` | Login providers: Settings → Providers → OMP instance → Accounts. No page shows `auth.broker.*`: set the URL in OMP's config or `OMP_AUTH_BROKER_URL`, the token in `OMP_AUTH_BROKER_TOKEN` or OMP's token file |
| Compaction `compaction.strategy`                              | `compaction.methodOrder` on Context; the pinned OMP has no `compaction.strategy`                                                                                                                               |
| Search provider order                                         | The `web` model role and its fallback chain, on Search                                                                                                                                                         |
| Runtime PTY                                                   | A read-only note on Runtime; OMP has no PTY setting                                                                                                                                                            |
| Plugins `omp plugin remove`                                   | `omp plugin uninstall`                                                                                                                                                                                         |

On mobile, Settings → OMP shows every page's fields as read-only summaries; editing stays on web
and desktop ([settings.md](settings.md#settings-pages)).
